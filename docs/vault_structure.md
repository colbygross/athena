# Obsidian Vault Structure & Workflow Layout

The **Obsidian Vault** serves as the human-readable markdown knowledge base for Athena OS. It is integrated with a sync agent daemon that bidirectionally updates checklists and formats logs into dashboard views.

*   **Vault Path**: [obsidian_vault/](../obsidian_vault/)
*   **Sync Logic Source**: `backend/agent.py`

---

## 1. Vault Directory Hierarchy

The vault layout organizes files by purpose, separation of concerns, and automated indexing:

```
obsidian_vault/
├── 01_Projects/                # Long-form project tracking notes (human-authored)
├── 02_Areas/                   # Category subfolders mapping to database tables
│   ├── Career/                 # Job description details, application logs
│   ├── Finances/               # Companion notes for receipts and bank exports
│   ├── Fitness/                # Reference notes. Contains Workout_Regimen.md
│   ├── Habits/                 # Daily habit registry records
│   ├── Health/                 # Medical lab checkups and doctor reports
│   └── Learning/               # Academic papers, CS study cheat sheets
├── 03_Resources/               # General bookmarks and reference documents
├── 04_Archives/                # Rolled retrospectives and old notes
├── Daily_Briefs/               # Auto-generated daily schedule briefs
├── Inbox/                      # Raw file drops staging folder (triggers LLM parser)
├── Summaries/                  # Main rolling summary logs
│   ├── Financial_Summary.md
│   ├── Health_Fitness_Summary.md
│   └── Learning_Career_Summary.md
├── calendar.ics                # Local calendar event store (synced ICS)
└── tasks.md                    # Core master task checklist (synced with DB)
```

## 2. Ingestion Companion Notes (YAML Frontmatter)

When a raw asset (e.g. Starbucks receipt image or medical lab PDF) is placed in `Inbox/`, the sync agent moves the raw asset to `storage/` and writes a **Companion Markdown Note** to the corresponding category under `02_Areas/`.

Each companion note is prepended with a structured YAML frontmatter block mapping metadata back to the SQLite table database rows:

```yaml
---
type: document-context
category: finances
original_name: invoice_xfinity.pdf
processed_at: 2026-05-26 19:10:45
meta_storage_relative_path: "2026-05-26_invoice_xfinity.pdf"
meta_amount: 85.00
meta_merchant: "Xfinity"
meta_date: "2026-05-26"
meta_type: "expense"
---

# Invoice Xfinity - 2026-05-26

Companion markdown note generated by Athena ingestion scanner. 
Original file registered in database and stored at storage/2026-05-26_invoice_xfinity.pdf.

## Summary Details
*   **Merchant**: Xfinity
*   **Amount**: $85.00
*   **Category**: Utilities / Internet
```

## 3. Auto-Generated Daily Brief Format

Morning briefs are generated daily by [backend/run_daily_brief.py](../backend/run_daily_brief.py) and stored at `Daily_Briefs/Daily_Brief_YYYY-MM-DD.md`. Below is the standardized layout:

```markdown
# Daily Brief — 2026-05-26

> Generated by Athena at 05:00:15

## 📅 Today's Schedule
- **10:00** (Google): Tech Interview with Datadog
- **14:00** (Local): Dentists Checkup

## ✅ Completed Today (2)
- [x] Unpack study desk items (general) at 09:30

## 🎯 Still Due Today (1)
- [ ] Implement Red-Black Tree deletion logic (learning)

## ⚠️ Overdue / Pushed Off (1)
- [ ] Measure PC case clearance length (general) — was due 2026-05-25 (1d overdue)

## 🔄 Habit Checklist
**1/5** habits completed today.
- [x] Code 1 Hour
- [ ] Read 10 pages *(not logged)*
- [ ] Workout *(not logged)*
- [ ] Drink 3L Water *(not logged)*
- [ ] Sleep 8 hours *(not logged)*

## 🏋️ Today's Workout Routine
**Routine**: Day 2: Lower Body Strength + Core
Reference: [[02_Areas/Fitness/Workout_Regimen|Workout Regimen]]

- [ ] Squats (or Goblet Squats) — 4 sets x 8-12 reps
- [ ] Romanian Deadlifts — 4 sets x 10 reps
- [ ] Walking Lunges — 3 sets x 12 reps per leg
- [ ] Hanging Leg Raises — 3 sets x 15 reps
- [ ] Plank Hold — 3 sets x 60 seconds
- [ ] Russian Twists — 3 sets x 20 reps per side
```

*   **Active Workout Split**: Resolves the cycle index using day calculation modulo 4. Appends exercise checkboxes directly as markdown tasks `- [ ]` and links back to the master [Workout_Regimen.md](../obsidian_vault/02_Areas/Fitness/Workout_Regimen.md) note.

## 4. Retrospective Retrospection Logs

At `23:59`, the script `backend/run_nightly.py` runs the retrospective flow:
1.  **Read Vitals & Logs**: Summarizes daily metrics recorded in database transaction lists, biometrics vitals, meals protein macros, and habit logs.
2.  **Retrospective Note**: Writes a daily log summary note inside `04_Archives/Daily_Summary_YYYY-MM-DD.md` for permanent retention.
3.  **Active Cleanup**: Deletes the morning brief from `Daily_Briefs/` to avoid cluttering active workspace directories.
